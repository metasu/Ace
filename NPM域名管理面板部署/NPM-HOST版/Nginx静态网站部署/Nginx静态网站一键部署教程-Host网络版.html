📌 简介与目标

目标：在一台全新的 Linux 服务器上，使用 Docker Compose v2 部署 Nginx 1.26 静态网站服务。

最终效果：

  • 访问 http://你的IP:50080 即可看到主页
  • 将 HTML 文件丢到 /opt/sites/ 即可对外提供访问
  • 支持子目录多站点：/opt/sites/站点名/index.html
  • 采用 network_mode: "host"，容器直接使用宿主机网络，获取真实访客 IP
⚠️ 端口占用提醒：Host 网络模式下，Nginx 将直接占用宿主机的 50080 和 50443 端口。请确保部署前这些端口未被其他程序使用。

架构：

组件版本用途
Docker Composev2容器编排
Nginx1.26静态文件服务
网络模式host直接使用宿主机网络，获取真实 IP

🔍 步骤 0 — 环境检查

0

docker --version

📁 步骤 1 — 创建目录结构

1
创建 Nginx 配置目录和站点目录

目的：建好所有必需的目录。

mkdir -p /opt/Nginx/conf /opt/Nginx/conf.d /opt/sites

目录说明：

目录用途
/opt/Nginx/Nginx Docker Compose 项目根目录
/opt/Nginx/conf/Nginx 主配置文件
/opt/Nginx/conf.d/站点配置文件（server 块）
/opt/sites/静态网站文件根目录

🐳 步骤 2 — 生成 docker-compose.yml

2
自动创建 Docker Compose 配置

目的：定义 Nginx 1.26 容器，挂载配置和站点目录，使用 Host 网络模式。

cat > /opt/Nginx/docker-compose.yml << 'EOF'
services:
  nginx:
    image: nginx:1.26
    container_name: nginx-1.26
    restart: unless-stopped
    network_mode: "host"
    volumes:
      - /opt/sites:/usr/share/nginx/html:ro
      - ./conf/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./conf.d:/etc/nginx/conf.d:ro
EOF
💡 说明：Host 网络模式下容器直接使用宿主机网络，Nginx 监听宿主机 50080（HTTP）和 50443（HTTPS）端口，无需端口映射。
⚠️ 安全提示：生产环境建议通过 NPM 反向代理 + SSL 访问。Host 模式下 NPM 的 Forward Hostname 填 127.0.0.1，Forward Port 填 50080。

⚙️ 步骤 3 — 生成 Nginx 配置

3
生成主配置和默认站点配置

4a — 主配置 nginx.conf

cat > /opt/Nginx/conf/nginx.conf << 'EOF'
user nginx;
worker_processes auto;
error_log /var/log/nginx/error.log warn;
pid /var/run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';

    access_log /var/log/nginx/access.log main;

    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;
    gzip on;

    include /etc/nginx/conf.d/*.conf;
}
EOF

4b — 默认站点配置 default.conf

cat > /opt/Nginx/conf.d/default.conf << 'EOF'
server {
    listen 50080;
    server_name _;
    root /usr/share/nginx/html;
    index index.html index.htm;

    location / {
        try_files $uri $uri/ =404;
    }
}
EOF
💡 说明：server_name _; 表示匹配所有域名。root 指向容器内的 /usr/share/nginx/html，即宿主机的 /opt/sites/。如需 HTTPS，可再添加监听 50443 的 server 块。

📂 新增站点（子目录方式）

方法极其简单：在 /opt/sites/ 下新建文件夹，放入 HTML 文件，即可访问。无需改任何配置，无需重启。

# 示例：新增一个名为 "blog" 的站点
mkdir -p /opt/sites/blog

cat > /opt/sites/blog/index.html << 'EOF'
<!DOCTYPE html>
<html>
<head><meta charset="UTF-8"><title>My Blog</title></head>
<body><h1>这是我的博客</h1></body>
</html>
EOF

立即可访问：

http://你的IP:50080/blog/

站点目录结构示例：

/opt/sites/
├── index.html              ← 主页（http://IP:50080）
├── blog/
│   └── index.html          ← http://IP:50080/blog/
├── docs/
│   └── index.html          ← http://IP:50080/docs/
└── tools/
    └── index.html          ← http://IP:50080/tools/
✅ 记住：丢文件夹 → 立即能访问，就这么简单。

🔁 NPM 反代 pCloud 短链接

场景：你有一个 pCloud 公开文件夹链接如 https://filedn.eu/你的pCloud_code/（例如 luAFbRWknPyfToYDs9VNNI8），想通过自有域名 https://你的域名/ 直接访问，隐藏冗长的 pCloud code 前缀，并支持在 WordPress 中 iframe 嵌入。

最终效果：

原始链接短链接
https://filedn.eu/你的pCloud_code/tut/file.htmlhttps://你的域名/tut/file.html
https://filedn.eu/你的pCloud_code/doc.pdfhttps://你的域名/doc.pdf
⚠️ 前置条件：你的域名 DNS A 记录已指向 NPM 服务器公网 IP，且 80/443 端口可达。

第 1 步 — NPM 面板 Details 标签：

字段填写
Domain Names你的域名（如 m.anut.top）
Schemehttps
Forward Hostname / IPfiledn.eu
Forward Port443

第 2 步 — SSL 标签：

  • SSL Certificate → Request a new SSL Certificate（Let's Encrypt）
  • ✅ 勾选 Force SSL
  • ✅ 勾选 HTTP/2 Support
  • ✅ 勾选 I Agree to the Let's Encrypt Terms of Service

第 3 步 — Advanced 标签（核心）：

清空默认内容，粘贴以下完整配置。请将 你的pCloud_code 替换为你的实际 code（如 luAFbRWknPyfToYDs9VNNI8），将 你的域名 替换为实际域名：

# ① 长链接自动 301 跳转到短链接
location ~ ^/你的pCloud_code/(.*)$ {
  return 301 https://你的域名/$1$is_args$args;
}

# ② 主代理（正则 location 优先级高于 NPM 默认的 location /）
location ~ ^/(?!\.well-known/) {
    proxy_ssl_server_name on;
    proxy_ssl_name filedn.eu;
    proxy_http_version 1.1;
    proxy_set_header Host filedn.eu;
    proxy_set_header Referer "";
    proxy_set_header Origin "";
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    proxy_set_header Accept-Encoding "";

    # 替换响应中的 pCloud 链接，让路径更简洁
    sub_filter '"code": "你的pCloud_code"' '"code": ""';
    sub_filter '"dirpath": "\/' '"dirpath": "';
    sub_filter '/你的pCloud_code/' '/';

    # 去掉跳转 pCloud 官网的链接
    sub_filter 'href="https://www.pcloud.com/"' 'href="/"';
    sub_filter 'https://www.pcloud.com/' '/';

    sub_filter_once off;
    sub_filter_types text/html text/css text/javascript application/javascript application/json;

    # 允许 iframe 嵌入 + 跨域
    proxy_hide_header X-Frame-Options;
    proxy_hide_header Content-Security-Policy;
    proxy_hide_header Access-Control-Allow-Origin;
    add_header Access-Control-Allow-Origin "*" always;
    add_header Access-Control-Allow-Methods "GET, HEAD, OPTIONS" always;
    add_header Content-Disposition "inline" always;

    # 断点续传 & 超时
    proxy_set_header Range $http_range;
    proxy_set_header If-Range $http_if_range;
    proxy_read_timeout 300s;
    proxy_send_timeout 300s;

    proxy_pass https://filedn.eu/你的pCloud_code$request_uri;
}
💡 原理说明：
配置项作用
location ~ ^/code/(.*)拦截残留的长路径，301 跳转到短链接
location ~ ^/(?!\.well-known/)正则 location 优先级高于 NPM 默认的 location /，接管所有请求（排除证书续签路径）
proxy_pass ...code$request_uri将短路径拼上 pCloud code 前缀后转发给上游
sub_filter "code"→"."pCloud JS 用 "/" + code + dirpath 拼链接，code 改为 "." 可避免双斜杠问题（/./tut/ 被浏览器规范化为 /tut/）
proxy_set_header Accept-Encoding ""禁止上游压缩，否则 sub_filter 无法替换内容
CORS / X-Frame-Options 头允许在 WordPress 等站点通过 iframe 嵌入

第 4 步 — 验证：

# 测试短链接直接访问
curl -sI https://你的域名/tut/file.html | head -5

# 测试长链接是否 301 跳转
curl -sI https://你的域名/你的pCloud_code/tut/file.html | grep location
✅ 期望：短链接返回 200，长链接返回 301 → https://你的域名/tut/file.html。

❓ 常见问题排查

Q1：访问 50080 端口显示 403 Forbidden
原因：/opt/sites/ 下没有 index.html 文件。
解决：确认文件存在： 
ls -la /opt/sites/index.html
Q2：容器启动失败 / 不断重启
诊断：
# 查看容器日志
cd /opt/Nginx && docker compose logs nginx

# 测试 Nginx 配置语法
docker exec nginx-1.26 nginx -t
Q3：端口 50080 已被占用
诊断并释放：
# 查看谁占用了 50080
ss -tlnp | grep ':50080'

# 方法一：停止占用该端口的程序
# 方法二：修改 /opt/Nginx/conf.d/default.conf 中的 listen 端口为其他值，然后重建容器
Q4：通过 NPM 反代后显示 502 Bad Gateway
原因：NPM 代理目标写错。
解决：由于 NPM 也使用 Host 网络模式，两者共享宿主机网络。NPM 的 Forward Hostname 填 127.0.0.1，Forward Port 填 50080。
Q5：Host 模式下容器 PORTS 列为空，正常吗？
正常。Host 网络模式下容器直接使用宿主机网络栈，不通过 Docker 端口映射，所以 docker ps 的 PORTS 列为空。用 ss -tlnp | grep ':50080' 确认端口监听即可。
Q6：中文文件名 URL 访问 404
原因：浏览器会对中文 URL 编码。建议文件名使用英文或拼音，避免中文路径问题。
Q7：NPM 反代 pCloud 后 Advanced 配置导致 ERR_SSL_UNRECOGNIZED_NAME_ALERT
原因：NPM 已自动处理 SSL/SNI，在 server 上下文重复添加 proxy_ssl_server_name 等指令会冲突。
解决：这些指令必须放在自定义的 location 块内（如教程所示），不能直接写在 Advanced 顶层。
Q8：NPM 反代 pCloud 目录页点击链接跳到 //tut/file（无头网址）
原因：pCloud JS 用 "/" + code + dirpath 拼链接，code 为空时产生双斜杠 //，被浏览器解析为协议相对 URL。
解决：将 sub_filter 中 code 替换为 "." 而非空字符串，/./tut/ 会被浏览器规范化为 /tut/。
Q9：NPM 的 rewrite 不生效，无法添加路径前缀
原因：NPM 内置的 proxy_pass 使用 $request_uri（原始请求 URI），而 rewrite 只修改 $uri，不影响 $request_uri。
解决：用自定义 location ~ 块覆盖默认路由，在其中直接写带路径前缀的 proxy_pass。

🧹 清理 / 回滚

如需完全卸载，按顺序执行以下命令：

🔴 警告：以下操作将删除 Nginx 容器、配置文件和所有站点数据，不可恢复。请确认后再执行。
# 1. 停止并删除容器和卷
cd /opt/Nginx && docker compose down --volumes --remove-orphans

# 2. 删除 Nginx 配置目录
rm -rf /opt/Nginx

# 3. 删除站点数据（⚠️ 会删除所有网站文件！）
rm -rf /opt/sites

# 4. 清理无用的 Docker 镜像（可选）
docker image prune -f
