1. 架构与工具清单

本方案在同一台机器上同时运行：网站/面板（宝塔）、反向代理与证书（NPM）、代理核心（sing-box 等）。各组件职责分离，避免抢端口。

1.1 最终架构

1
宝塔面板：站点管理、PHP/MySQL 等；Nginx 监听 10080/10443（让出 80/443）；MySQL 默认 3306
2
Docker Engine + Compose V2：运行 NPM 与 MariaDB
3
Nginx Proxy Manager（Host 网络）：占 80/443/81；申请/续期 Let's Encrypt；可选反代
4
v2ray-agent 脚本（install.sh）：安装 sing-box / Xray 等；协议示例：Reality + AnyTLS
5
证书链路：NPM 申请 → 软链到 /etc/v2ray-agent/tls/ → 脚本/核心读取；续期靠 NPM

1.2 使用的工具与文件

重要原则
  • 80/443 给 NPM（Host），不要给宝塔、不要给脚本系统 Nginx。
  • 翻墙核心用自定义端口（如 8443、2053），避开 80/443/81。
  • 数据库：宝塔 MySQL 3306 与 NPM MariaDB 13306 默认不冲突；勿把 NPM 改成 3306。
  • 证书优先用 NPM 申请 + 软链；脚本侧选「不重新安装证书」。
  • 脚本可能 apt 安装系统 Nginx —— 装完后卸载系统包，勿动宝塔 Nginx 与 NPM。

2.1 数据库端口是否冲突？

结论：默认不冲突，可同时运行。
组件进程 / 路径端口用途
宝塔 MySQL mysqld → /www/server/mysql 3306 宝塔站点、面板业务库
NPM MariaDB 容器 Host 网络 → mariadbd --port=13306 13306 仅 NPM 自身数据（代理主机、证书元数据等）
  • npm-host.sh 在 Host 模式下故意使用 13306，避免与本机常见 3306 抢端口。
  • 两套库数据互不相通：宝塔库管网站，NPM 库只管面板自己。
  • 宝塔连接数据库仍用 3306；不要把 NPM 的 MYSQL_PORT 改成 3306，否则会冲突。
  • NPM 的 13306 可能监听 0.0.0.0：防火墙不要对公网开放 13306（仅本机访问即可）。
  • 检查命令：
ss -tlnp | grep -E ':(3306|13306)\b'
# 预期示例：
# 3306  → mysqld（宝塔）
# 13306 → mariadbd（NPM）

grep MYSQL_PORT /opt/npm/.env

5. 宝塔 Nginx 端口 80/443 → 10080/10443

完整 sed 列表见：/www/notes/宝塔Nginx修改默认端口80-443到10080-10443.md。以下为精简实操版。

5.1 备份

TS=$(date +%Y%m%d_%H%M%S)
mkdir -p /www/backup/panel/nginx_port_change_$TS
cp -a /www/server/panel/vhost/nginx /www/backup/panel/nginx_port_change_$TS/
cp -a /www/server/panel/class/{panelSite.py,sites.py,firewalls.py,firewall_new.py,public.py,ajax.py,setPanelLets.py} \
  /www/backup/panel/nginx_port_change_$TS/

5.2 修改 vhost 监听

sed -i 's/listen 80;/listen 10080;/' /www/server/panel/vhost/nginx/phpfpm_status.conf
# 批量替换（已包含 0.default.conf）
sed -i 's/listen 80;/listen 10080;/g' /www/server/panel/vhost/nginx/*.conf 2>/dev/null
sed -i 's/listen 443 ssl/listen 10443 ssl/g' /www/server/panel/vhost/nginx/*.conf 2>/dev/null
sed -i 's/listen \[::\]:80;/listen [::]:10080;/g' /www/server/panel/vhost/nginx/*.conf 2>/dev/null
sed -i 's/listen \[::\]:443 ssl/listen [::]:10443 ssl/g' /www/server/panel/vhost/nginx/*.conf 2>/dev/null

5.2a 关键：默认站 0.default.conf 必须改

0.default.conf 是宝塔兜底页面，默认监听 80。部署 NPM（Host）后，80 被 NPM 占用，会导致整个宝塔 Nginx 无法启动，所有宝塔站点（包括 127.0.0.1:15669 这种自定义端口站点）都会变成 Connection refused。

改完后的检查：

grep -n 'listen' /www/server/panel/vhost/nginx/0.default.conf
# 预期只有：listen 10080;

常见报错现象：

  • ss -tlnp | grep 15669 无结果
  • 宝塔 Nginx 日志：bind() to 0.0.0.0:80 failed (98: Address already in use)
  • NPM 反代报错：connect() failed (111: Connection refused) while connecting to upstream, upstream: "http://127.0.0.1:15669/"

5.4 重载与防火墙

/www/server/nginx/sbin/nginx -t
# 如果之前因 80 冲突没启动，先 reload 再检查
/www/server/nginx/sbin/nginx -s reload
ss -tlnp | grep -E '10080|10443|[:.]80\b|[:.]443\b'

# 确认宝塔默认站已改 10080
grep -n 'listen' /www/server/panel/vhost/nginx/0.default.conf

# 确认宝塔站点自定义端口（如 15669）已监听
ss -tlnp | grep 15669

# UFW 示例
ufw allow 10080/tcp
ufw allow 10443/tcp
# 云安全组同步放行 10080、10443
预期：宝塔 Nginx 监听 10080；宿主机 80/443 已空闲，留给 NPM；宝塔站点（如 15669）可正常访问。
宝塔升级可能覆盖 Python 及 vhost 配置，升级后需检查 0.default.conf 是否又被改回 80。
如果你在宝塔面板里设置了伪静态（WordPress）后内页仍 404，通常是因为修改后没有触发 Nginx 重载。手动执行一次 /www/server/nginx/sbin/nginx -s reload 即可。

8. 用 NPM 申请证书并软链给脚本

8.1 在 NPM 申请证书

  1. 打开 http://IP:81 → SSL Certificates → Add SSL Certificate → Let's Encrypt
  2. 域名填：fr.plai.top（换成你的域名）
  3. 推荐 DNS Challenge（如 Cloudflare），不依赖 80 验证，续期更稳
  4. 申请成功后，证书可能显示 Not Used —— 正常，表示尚未挂到 Proxy Host，仍会自动续期

8.2 确认磁盘路径

ls -la /opt/npm/npm_letsencrypt/live/
# 常见为 npm-1、npm-2 ...
openssl x509 -in /opt/npm/npm_letsencrypt/live/npm-2/fullchain.pem -noout -subject -dates
# 确认 CN/SAN 为你的域名

下面示例目录为 npm-2，请按实际 live 目录名替换。

8.3 软链到脚本目录

DOMAIN=fr.plai.top
LIVE_DIR=/opt/npm/npm_letsencrypt/live/npm-2   # 改成实际目录

mkdir -p /etc/v2ray-agent/tls
ln -sfn "$LIVE_DIR/fullchain.pem" "/etc/v2ray-agent/tls/${DOMAIN}.crt"
ln -sfn "$LIVE_DIR/privkey.pem"   "/etc/v2ray-agent/tls/${DOMAIN}.key"

ls -la /etc/v2ray-agent/tls/${DOMAIN}.*
openssl x509 -in /etc/v2ray-agent/tls/${DOMAIN}.crt -noout -subject -dates
续期说明
  • NPM 容器运行中会自动续期 LE 证书（约 90 天一轮）。
  • 软链指向 live/npm-* 固定路径，续期后一般无需重链。
  • 面板显示 Not Used 不影响续期。
  • 若代理核心启动时读入证书，续期后可能需重启 sing-box/xray 加载新证。

10. 卸载脚本安装的系统 Nginx

只卸载 apt 系统 nginx。不要删除：
  • /www/server/nginx（宝塔）
  • NPM 容器
  • /usr/bin/nginx 若指向宝塔 sbin（软链）——卸载 apt 包后可能仍保留宝塔软链，属正常
# 确认系统包存在
dpkg -l | grep -i nginx
ls -la /usr/sbin/nginx /etc/nginx 2>/dev/null

systemctl stop nginx 2>/dev/null
systemctl disable nginx 2>/dev/null
apt-get remove --purge -y nginx nginx-common nginx-core
rm -f /etc/apt/sources.list.d/nginx.list /etc/apt/preferences.d/99nginx
rm -rf /etc/nginx
apt-get autoremove -y
systemctl reset-failed nginx 2>/dev/null
systemctl daemon-reload
hash -r

# 验收：系统包应消失；80/443 仍为 NPM
dpkg -l | grep -i '^ii.*nginx' || echo 'no apt nginx'
ss -tlnp | grep -E ':(80|443|81)\b'
docker ps | grep npm
test -x /www/server/nginx/sbin/nginx && echo 'BT nginx OK'
ls -la /etc/v2ray-agent/tls/

13. 常见问题

Q1：脚本为什么还装 Nginx？

协议组合（如 7,13）未命中脚本「免 Nginx」白名单（主要针对纯 Reality 等）。装完按第 10 节卸载即可。

Q2：NPM 证书显示 Not Used？

未绑定 Proxy Host 时的正常状态，不影响自动续期，也不影响软链给脚本使用。

Q3：自定义证书无法 renew？

脚本发现软链证书后会跳过 acme 续期。续期交给 NPM；这是预期行为。

Q4：80 被占用装不了 NPM？

先完成第 5 节宝塔改端口，确认 ss -tlnp 无宿主机 80/443 再部署 NPM。常见遗漏：宝塔默认站 0.default.conf 仍监听 80，会导致宝塔 Nginx 无法启动。

Q5：宝塔自定义端口站点（如 15669）无法通过 NPM 反代访问？

可能不是 NPM 反代问题，而是宝塔 Nginx 没启动。检查：

  • ss -tlnp | grep 15669 是否有监听？
  • grep -n 'listen' /www/server/panel/vhost/nginx/0.default.conf 是否还是 80？
  • 宝塔 Nginx 日志是否出现 bind() to 0.0.0.0:80 failed？

解决方法：将 0.default.conf 改为 listen 10080;，然后重载宝塔 Nginx。

Q6：PUBLIC_IP 变成 IPv6？

npm-host 用 ifconfig.me 探测时可能拿到 IPv6。访问面板请用公网 IPv4：http://x.x.x.x:81。

Q7：卸载系统 nginx 会不会弄坏宝塔？

不会。宝塔使用 /www/server/nginx/sbin/nginx。卸的是 apt 的 /usr/sbin/nginx 与 /etc/nginx。

Q8：推荐协议怎么选？

  • 抗封锁直连：Reality（7）
  • 需要域名真证书 TLS：AnyTLS（13）等，配合 NPM 证书软链
  • 仅 CDN：WS 类（需 Nginx/反代，与本「卸系统 nginx」方案不同）

Q9：宝塔数据库端口和 NPM 冲突吗？

不冲突。宝塔 MySQL 默认 3306，NPM（Host）MariaDB 默认 13306，是两套独立数据库。

  • 检查：ss -tlnp | grep -E ':(3306|13306)\b'
  • 配置：grep MYSQL_PORT /opt/npm/.env 应为 13306
  • 切勿把 NPM 的 MYSQL_PORT 改成 3306
  • 13306 / 3306 均建议不对公网开放

Q10：WordPress 经 NPM 反代后页面样式异常（CSS/JS 加载失败）？

通常是 WordPress 生成的资源地址是 http://，而浏览器通过 https:// 访问，触发混合内容拦截，导致 CSS/JS 无法加载，页面变形。

在站点 wp-config.php 的 /* Add any custom values... */ 与 /* That's all, stop editing... */ 之间添加：

/** NPM 反向代理：强制站点地址为 HTTPS */
define( 'WP_HOME', 'https://your-domain.com' );
define( 'WP_SITEURL', 'https://your-domain.com' );

/** 信任 NPM 的 X-Forwarded-Proto 头，让 WordPress 识别 HTTPS */
if ( isset( $_SERVER['HTTP_X_FORWARDED_PROTO'] ) && 'https' === $_SERVER['HTTP_X_FORWARDED_PROTO'] ) {
    $_SERVER['HTTPS'] = 'on';
}

/** 后台强制 HTTPS（可选） */
define( 'FORCE_SSL_ADMIN', true );
  • 将 your-domain.com 换成你的实际域名（如 ace.lc）。
  • NPM 默认会传递 X-Forwarded-Proto: https，无需额外配置。
  • 若已登录后台，修改 wp-config.php 后清除浏览器缓存再刷新。
  • 少数主题/插件仍写死 http:// 外链，需手动替换或修改主题。

Q11：WordPress 内页（如 /vip/）设置伪静态后仍 404？

宝塔面板设置伪静态后，有时不会自动触发 Nginx 重载。手动执行：

/www/server/nginx/sbin/nginx -t
/www/server/nginx/sbin/nginx -s reload

然后再刷新 https://your-domain.com/vip/。如果还 404，进入 WordPress 后台 → 设置 → 固定链接 → 直接点击「保存更改」刷新重写规则。
